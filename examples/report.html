Scope and interpretation

Compared: user tables; column names, types and nullability; primary-key columns, order, direction and clustering; SQL procedure, view and function definitions with ANSI_NULLS and QUOTED_IDENTIFIER; synonym target names; CLR scalar/table-valued functions (FS/FT) by assembly identity/permission set/main-DLL SHA-256, class/method, ordered parameter/default/return signatures, EXECUTE AS and NULL ON NULL INPUT.

Not compared: row data, table column order/defaults/identity/computed expressions/collation, non-PK indexes, FK/CHECK/UNIQUE constraints, constraint names, triggers, object GRANT/DENY permissions, type/XML schema definitions and other advanced properties. CLR dependency assemblies, ancillary assembly files and instance-level CLR settings are excluded.

Names are case-sensitive. SQL hunks show the original definitions. In normalized mode, ignored declaration changes can appear alongside other differences. Synonym targets are compared by name, not by connecting to the referenced object.

CLR metadata is compared independently of SQL mode; it is not a T-SQL definition diff. Missing or changed CLR functions require manual assembly/function migration.

Encrypted or unreadable SQL definitions/CLR metadata and unsupported CLR procedures (PC), aggregates (AF) or extended procedures (X) cause an error rather than being silently skipped. Database-level VIEW DEFINITION and readable CLR assembly bytes are required; object-level DENY can hide metadata. Avoid concurrent schema changes because the databases are read sequentially.
